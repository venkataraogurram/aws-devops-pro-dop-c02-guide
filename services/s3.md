# Amazon S3 (events, integrity, protection)

**Exam domains:** [Domain 1](../01-sdlc-automation.md), [Domain 3](../03-resilient-cloud.md), [Domain 4](../04-monitoring-logging.md), [Domain 5](../05-incident-event-response.md), [Domain 6](../06-security-compliance.md) | **Hands-on:** [Lab 16](../labs/16-multi-region-dr/README.md)

> Replication is covered in [Databases and storage](databases-storage.md). Encryption is in [KMS](kms-cloudhsm.md). Exam scenarios are in each domain's quick-map table.

## S3 Event Notifications
- Events: object created (`s3:ObjectCreated:*`, Put, Post, Copy, CompleteMultipartUpload), removed, restored, replication events, lifecycle events, tagging/ACL changes. Filter by **prefix and suffix** (e.g., `logs/` and `.gz`).
- Destinations: **SNS topic, SQS queue, Lambda function**, or **EventBridge** (turn on "Send notifications to EventBridge" for the bucket).
- **Permissions**: the destination's **resource policy** must allow S3 to send (SNS topic policy / SQS queue policy / Lambda resource-based permission for `s3.amazonaws.com`, ideally with `aws:SourceArn` = bucket ARN and `aws:SourceAccount`). Not an IAM role.
- Delivery is usually within seconds, can take a minute or longer. Design consumers to be idempotent.
- **Why use EventBridge instead**: advanced filtering (object size, metadata, name patterns), many targets per rule (Step Functions, Kinesis, ECS tasks...), archive and replay, cross-account buses.
- Classic exam pattern: new log file in S3 -> Lambda parses it -> loads into OpenSearch / CloudWatch Logs / DynamoDB.

## Object integrity
- Send a `Content-MD5` header on upload; S3 rejects the upload if its computed MD5 doesn't match.
- **ETag**: for a single-part upload that is unencrypted or SSE-S3 encrypted, the ETag is the object's MD5. For multipart uploads or SSE-KMS, the ETag is **not** the MD5.
- Additional checksum algorithms: CRC32, CRC32C, CRC64NVME, SHA-1, SHA-256 (S3 now calculates a CRC-based checksum by default for new uploads). Retrieve with `GetObjectAttributes` / `HeadObject` to verify after download or replication.

## Protecting data
- **Versioning** (recover overwritten/deleted objects), **MFA Delete** (root only, CLI only), **Object Lock** (WORM: governance or compliance mode, retention periods, legal hold; needs versioning), **Block Public Access** (account and bucket level), **Object Ownership = bucket owner enforced** (ACLs disabled).
- **Lifecycle rules**: transition to Standard-IA / One Zone-IA / Glacier Instant / Flexible / Deep Archive; expire current or noncurrent versions; abort incomplete multipart uploads.
- **Access logging**: server access logs (best effort) or CloudTrail data events (reliable, per API call).
